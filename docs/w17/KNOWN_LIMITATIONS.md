# Known limitations and residual risks (consolidated, Week 17)

Each item says what is limited, who is affected, how it is mitigated today, and when it must be resolved. "Source" points to where it was found. Ratings: **P** = must fix before production, **R** = pilot risk to monitor, **N** = accepted / nice to have.

| ID | Limitation | Impact | Mitigation now | Resolve | Source |
|---|---|---|---|---|---|
| L-01 | Exactly one API instance may run: single-writer file store; lockout, revocation and rate counters live in process memory | No redundancy; a host failure is an outage until restart | Fast restart (0.9 s), health-gated deploy, runbook | **P** shared database and shared counters (ADR-001, ADR-004) | W14 R2, W16 |
| L-02 | Comfortable up to about 10,000 stored reports: every write serialises the whole data set (create p95 94 ms at 10,000, 258 ms at 25,000) | Slower writes as data grows | Alert at 8 MB; archive closed reports | **P** database (ADR-001) | W16 |
| L-03 | Closed reports and the audit trail are never trimmed | File and memory grow without bound | Manual archive | **P** retention job and append-only audit store | W16 |
| L-04 | Backup copy is rotated at most every `BACKUP_INTERVAL_MS` (default 60 s) and lives next to the data file | Corruption recovery can lose up to that interval; a disk loss loses everything | Set interval to about 5 s; copy `db.json` off the machine regularly | **R** documented procedure; **P** DB backups | W16 |
| L-05 | No multi-factor authentication; passwords are managed locally; demo accounts use fixed test-only passwords | Weak identity assurance if exposed | Controlled test accounts only; never reuse | **P** institutional SSO/OIDC (ADR-003) | W14 R6 |
| L-06 | One shared HMAC signing secret, no rotation | Secret compromise lets an attacker mint any role | Environment-only secret, never logged; rotate quarterly (invalidates sessions) | **P** key rotation or asymmetric keys | W14 R4 |
| L-07 | Lockout, revoked-token list and rate counters reset on restart | A restart clears lockouts and logout revocations | Short token life (15 min) | **P** with L-01 | W14 R2 |
| L-08 | Per-account lockout can be used to lock out a victim for 15 minutes | Nuisance denial of service on one user | Window is short; per-IP limits | **N** | W14 R3 |
| L-09 | 15-minute sessions with no refresh and no expiry warning | Staff mid-task are asked to sign in again at the next action | Clear "Sign in again" screen | **R** refresh tokens under OIDC | W14 R7, UAT F12 |
| L-10 | Notification delivery runs inside the create-report request | A slow real gateway slows every submission | Simulated instant channel in the pilot | **P** outbox and worker before a real gateway (ADR-002) | W13, W16 |
| L-11 | Matching has no synonyms and forgives no typos | Missed matches when wording differs | Human review; owner can add a second report | **R** measure in pilot, then synonym table (ADR-005) | W15 R11 |
| L-12 | Conflict-of-interest rule covers the claimant only | Two colluding staff could release an item wrongly | Role separation, audit trail with proof notes | **R** dual approval for high-value items | W15 R14 |
| L-13 | Release records no handover details (who collected, ID checked) | Weak physical chain of custody | Proof note recorded at verification | **R** add a handover record | UAT F11 |
| L-14 | The Reports screen has no search, filter or sort; the app loads the first 200 | Staff must scroll | API supports paging | **N** | UAT F10 |
| L-15 | First visit downloads about 9.7 MB (3.6 MB gzip), mostly the renderer | Slow first load on a weak connection; real-browser timings not measured | Splash screen, host compression and caching (D01-D04) | **R** measure on the real host | W16, UAT F6 |
| L-16 | No automated browser end-to-end test; Flutter tests use a mocked API; the browser retest could not complete the confirm-release-student steps (automation stopped delivering keystrokes) | UI regressions between mock and real server could slip through | Contract tests, scripted UAT against a live server, widget tests | **R** integration test with a real browser | W15 R12, W17 |
| L-17 | Load tests ran on one machine over loopback, seconds long, with an instant simulated channel | Real-network latency, long-run leaks and gateway behaviour are unmeasured | Conservative interpretation, 40x headroom | **R** soak and network test on the real host | W16 |
| L-18 | Logs and audit entries are not tamper-evident (stdout plus a 500-line in-memory ring; audit in the data file) | An administrator could alter history | Audit entries include actor and action; proof notes | **P** append-only central logging | W14 R8 |
| L-19 | Phone-width legibility was checked only by an automated layout test (no overflow at 400 px), not by eye; the app-bar title truncates | Possible readability issues on small screens | Responsive bottom navigation | **N** device check in UAT with real users | UAT F13 |
| L-20 | Report dates are calendar days without time zones; the allowed window uses UTC plus one day | Edge cases around midnight in unusual zones | Tested for UTC+8 (the campus) | **N** | W15 D1 |
| L-21 | No formal accessibility audit (screen reader, colour contrast, keyboard use) | Possible barriers for some users | Standard Material widgets | **R** audit before wider rollout | W17 |
| L-22 | No approved privacy notice or retention schedule; descriptions are free text and may contain personal details | Data kept longer than needed | Data minimisation in responses; test data only | **P** retention policy and notice (proposal in MAINTENANCE.md) | W17 |
| L-23 | Security headers and cache rules for the static host depend on the real host/CDN configuration | A misconfigured host could serve stale or unprotected files | Reference behaviour defined and tested (D01-D04) | **R** verify on the real host | W14 R9, W17 |
| L-24 | The Node 20.10 `node --test` child-process mode occasionally left a finished test process spinning at 100% CPU so the run never returned (3 times in about 35 runs; none in 72 direct runs); root cause not identified. A rare, unexplained spin could also, in principle, be something the production process does | A stuck test run delays a release or a verification | `npm test` runs each file directly with a hard timeout so a stuck file fails loudly; no hang or spin was ever observed in the running API or in the load and rehearsal runs | **R** keep the timeout; investigate if it recurs outside the test runner, or upgrade Node and retest | W18 |
